# Data Model: Order-Owned Reservation Expiry

## Order Reservation Request

This is a transient API/domain input, not a database table.

| Field | Type | Rules |
|---|---|---|
| `orderId` | UUID | Required caller-supplied order identifier; identifies one durable reservation set. |
| `expiresAt` | RFC 3339 timestamp / UTC `time.Time` | Required explicit-offset instant with at most microsecond precision; normalized to UTC; must be strictly later than database creation time for a new set. |
| `items` | non-empty list | Each element has a unique public product `variantId` and positive whole-number `qty`. |

The request's canonical identity is its sorted `(variantId, qty)` set plus its normalized
expiry instant. Caller item order and equivalent offset representations do not change
that identity.

## Reservation

`reservations` is the sole durable source for order association and retry outcome.

| Field | Type | Rules |
|---|---|---|
| `id` | UUIDv7 | Generated by the use case. |
| `inventory_item_id` | UUID | Required existing inventory item resolved from the public variant. |
| `location_id` | UUID | Required selected default fulfillment location. |
| `order_id` | UUID | Required on every row for an order; identifies the reservation set. |
| `quantity` | integer / `domain.Quantity` | Positive whole number; retained `quantity > 0` constraint. |
| `reserved_at` | `timestamptz` | One database `clock_timestamp()` captured for the new order set. |
| `expires_at` | `timestamptz` | Caller-owned normalized instant; same for every new row in the set and strictly after `reserved_at`. |
| `status` | reservation status | New rows are `ACTIVE`; later lifecycle work can transition them. |
| `released_at` | nullable `timestamptz` | Reserved for later lifecycle work. |

The existing unique `(order_id, inventory_item_id)` constraint remains the duplicate-item
backstop. Its leading `order_id` also supports order-set lookup. Existing historical rows
and recorded expiry values are not changed.

### Idempotency lifecycle

```text
new order_id
  -> transaction advisory lock
  -> no rows: validate expiry, reserve inventory, insert ACTIVE set, commit

existing order_id
  -> transaction advisory lock + FOR UPDATE reservation rows
  -> same canonical variants, quantities, and expiry: return persisted set
  -> any difference: ERR_RESERVATION_CONFLICT, no writes
```

`pg_advisory_xact_lock` is ephemeral transaction coordination, not a durable entity.
It protects the otherwise-unlockable zero-row case. The reservation rows remain the only
durable request record.

## Removed CheckoutReservationRequest

`checkout_reservation_requests(order_id, request_fingerprint, created_at)` is removed
by migration 0006 after rollout. Its fingerprint and claim timestamp are not copied to a
new table or column. The reservation set supplies the needed facts directly.

## Inventory level and stock movement

| Entity | Reservation rule |
|---|---|
| `InventoryItem` | Resolves from a non-deleted, tracked public variant. |
| `InventoryLevel` | The default-location row is locked in deterministic inventory-item order. On success, available decreases and reserved increases by exactly the reservation quantity. |
| `StockMove` | Exactly one `RESERVE` movement is inserted for each new reservation using the existing `stock_moves` columns. Retries add none. |

Every new order set preserves the existing one-transaction boundary for inventory levels,
reservations, and stock movements. A validation, conflict, expiry, or availability failure
rolls back all new changes.

## Domain contract changes

| Current contract | Planned change |
|---|---|
| `Create(ctx, orderID, items)` | Add normalized caller expiry to the use-case input. |
| `CreateReservationInput{OrderID, Fingerprint, Items}` | Replace `Fingerprint` with the normalized `ExpiresAt` instant. |
| `fingerprintRequest` and parent-request row model | Remove; compare the persisted reservation set instead. |
| Seconds-only response expiry format | Use RFC3339Nano so a stored microsecond instant is not truncated. |

## Errors

| Error code | HTTP status | Meaning |
|---|---:|---|
| `ERR_INVALID_EXPIRY` | 400 | `expiresAt` is absent, malformed, lacks an explicit offset, or cannot be stored without precision loss. |
| `ERR_EXPIRED_EXPIRY` | 422 | A parsed expiry is current or past at authoritative reservation creation time. |
| `ERR_RESERVATION_CONFLICT` | 409 | An existing order's persisted set differs in items, quantities, or expiry instant. |
| existing inventory/validation/coordination codes | existing statuses | Continue to describe independent item, stock, location, and coordination failures. |
